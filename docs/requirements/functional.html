Функциональные требования (FR)

Требования описаны для версии MVP 1.0

Список требований​

FR-DC — Сбор и обработка данных​

IDТребование
FR-DC-001Система должна подключаться минимум к двум источникам данных (MES/ERP)
FR-DC-002Система должна собирать данные по расписанию (например, каждые 10 минут)
FR-DC-003Система должна обрабатывать все получаемые типы данных
FR-DC-004Система должна хранить данные во внутреннем хранилище (БД)
FR-DC-005Система должна применять фильтрацию к данным

FR-RG — Генерация справок​

IDТребование
FR-RG-001Система должна формировать справку по шаблону
FR-RG-002Система должна подставлять актуальные данные в шаблон
FR-RG-003Система должна использовать ИИ-агента для интерпретации данных

FR-CI — Чат-интерфейс​

IDТребование
FR-CI-001Пользователь должен иметь возможность вводить текстовый запрос
FR-CI-002Система должна возвращать пользователю ответ
FR-CI-003Интерфейс должен отображать историю диалога

FR-DV — Дашборды​

IDТребование
FR-DV-001Система должна формировать дашборды на основе актуальных данных
FR-DV-002Пользователь должен иметь возможность применять фильтры к дашборду
FR-DV-003Система должна формировать дашборды по шаблонам пользователей

Use Cases​

UC-DC-001 — Подключение к источнику данных (MES)​

Акторы: Инженер АСУ ТП, MES-система, Сервис интеграции

Предусловия:

  • У инженера есть права доступа к настройкам интеграции
  • Доступ к MES открыт: хост, порт, параметры аутентификации
  • Система развёрнута и может выполнять запросы

Основной поток:

  1. Инженер открывает экран настроек интеграции
  2. Выбирает тип источника «MES»
  3. Вводит параметры подключения (адрес, метод, логин/пароль)
  4. Система проверяет соединение
  5. MES возвращает результат успешного подключения
  6. Система сохраняет параметры
  7. Источник отображается в списке подключённых

Альтернативные потоки:

  • A1: Инженер выбирает альтернативный протокол (API) → подключение через API → при успехе продолжается основной поток

Исключительные потоки:

  • E1: Ошибка соединения → система показывает сообщение об ошибке → пользователь исправляет данные и повторяет
  • E2: Ошибка сохранения → система предлагает повторить позже

Критерии приёмки:

  • Пользователь может ввести параметры подключения
  • При нажатии «Проверить» система выполняет попытку соединения
  • Если источник недоступен — выводится сообщение об ошибке
  • После успеха параметры сохраняются
  • Система позволяет создать не менее двух подключений
  • Все операции фиксируются в логах

UC-RG-001 — Формирование справки по шаблону​

Акторы: Пользователь, Система

Предусловия:

  • В системе есть шаблон справки
  • Система содержит актуальные данные

Основной поток:

  1. Пользователь вводит запрос на формирование справки в чат
  2. Система принимает запрос в обработку
  3. Система подставляет в шаблон актуальные данные
  4. Данные передаются ИИ-агенту для интерпретации
  5. ИИ-агент обрабатывает данные согласно инструкциям
  6. Результат возвращается пользователю в чат

Исключительные потоки:

  • E1: Ошибка получения шаблона/данных → сообщение пользователю, лог ошибки, уведомление администратора
  • E2: Ошибка отображения результата → пустой результат → пользователь сообщает об ошибке
  • E3: Галлюцинации ИИ → пользователь сообщает об ошибке → фиксация и уведомление администратора

UC-CI-001 — Отображение истории запросов​

Акторы: Пользователь, Система

Основной поток:

  1. Пользователь открывает чат
  2. Нажимает «Загрузить историю»
  3. Система возвращает и отображает историю
  4. Пользователь открывает любой исторический запрос

Альтернативные потоки:

  • A1: Пользователь выбирает период → система фильтрует → отображает результат

UC-DV-001 — Применение фильтров к дашбордам​

Акторы: Пользователь, Система

Основной поток:

  1. Пользователь открывает окно дашбордов
  2. Выбирает дашборд
  3. Система отображает дашборд и список фильтров
  4. Пользователь выбирает фильтры
  5. Система применяет фильтры и обновляет дашборд

Критерии приёмки:

  • Фильтрация применяется с задержкой < 2 секунд
  • Система отображает допустимый диапазон значений для фильтров
